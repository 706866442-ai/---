# 双轮速度 PID：已实现模块，待接入实物反馈

更新：2026-10-13。

`lib/WheelSpeedControl/src/` 已加入硬件无关的双轮速度控制模块；
`tests/wheel_speed_test.cpp` 是电脑端行为测试。
当前 `src/main.cpp` 仍运行灰度板 I²C 通信检测。本次没有更改或烧录主程序，
PID 尚未接入编码器中断、PWM 或电机启动流程，不能据此认为车已能闭环直行。

## 控制关系

给定左右轮目标线速度 → 分别减去编码器测得的轮速 → 两个 PID → 两侧 PWM。

`straight()` 为两轮设置相同的目标线速度；`update()` 可设置不同的目标速度，
留给后续灰度循迹外环使用。仅靠轮速一致无法修正轮胎打滑、车轮几何误差，
也无法让已经偏离黑线的车自动回到线上；循迹还需读取灰度位置误差。

## 接入接口

1. 先让电机处于停止状态，用手转动轮子验证 A/B 计数；车辆前进方向计数为正。
2. 每约 20 ms 原子地取出两轮本周期计数增量，使用同一个实际采样时间。
3. `mmPerCount = 车轮周长(mm) / 车轮每转的实际解码计数`。左右分别标定，
   不要把电机轴脉冲数、减速比和 x1/x2/x4 解码计数混为一谈。
4. 调用 `straight(目标毫米每秒, 左计数增量, 右计数增量, 周期秒数, 允许运行)`。
5. `valid == false` 时适配层必须立即停止两电机；否则将有符号的 PWM 输出分别交给
   TB6612 方向与占空比控制。正值必须对应车辆前进，PWM 范围按 8 位 0～255。
6. 接入前删除主循环中数秒的 `delay()`，LED 改为非阻塞计时；I²C 超时不能阻塞
   速度环。当前模块拒绝 1～50 ms 之外的采样周期，但它本身不具备独立硬件停机能力。

模块带输出限幅、积分限幅、饱和时抑制积分累积、测量微分低通和停机清除积分。
目标为零时输出零，不实现主动位置保持。PID 可能输出反向制动力，首次联调必须
验证正反方向和驱动能力。编码器断线会表现为零速，仅凭该值无法区分停转与断线；
硬件适配层必须加入无反馈/堵转超时停止、启动条件和明确停止操作后，才可启用驱动。

## 调试顺序

- 先确认供电故障已排除、主控/驱动/编码器电平兼容，保持旧板断电。
- 架空车轮，验证两电机方向及编码器正负号，再标定每轮实际计数。
- 先设 Ki=Kd=0，低速限幅逐步调 Kp；再少量加入 Ki 消除稳定速度误差。
- Kd 可先为零；编码器低速量化噪声较大，不能直接套网上 PID 数值。
- 对比目标速度、实测速度、左右 PWM，再落地短距离试直线。
- 灰度读数稳定后加入位置外环，产生两轮不同目标速度以修正路线。

电脑测试覆盖负反馈方向、正反转、输出限幅、积分抗饱和、停机复位、异常输入、
目标跳变的微分响应、左右不同计数比例，以及两个不同电机模型的速度收敛。
仿真参数仅用于测试，不是实车 PID 参数。还没有进行实车闭环验证。

实现参考：[WPILib PID 控制说明](https://docs.wpilib.org/en/stable/docs/software/advanced-controls/controllers/pidcontroller.html)。
