# 灰度板 I²C 连通测试

这个测试程序只检查感为八路灰度板是否响应 I²C 地址 0x4C～0x4F，不启动电机，也不读取八路黑白数据。2026-10-13 已重新烧录到更换后的 STM32，校验通过，用户反馈程序运行正常；灰度板通信尚未验证成功。

## 供电与接线

统一查看 [当前接线总表](../接线总表.md) 第 2、5、6 节，以该表区分规划与实物状态。
当前程序使用 SCL=PB10、SDA=PB11；供电、电平及上拉要按实际线路核对。
旧板曾冒烟，当前外部供电故障原因未查明，不凭旧示例直接恢复电源连接。

## 烧录

1. 在 VS Code 打开本文件所在文件夹 `gray_i2c_probe`。
2. 连接原来的 ST-LINK V2（SWDIO→PA13、SWCLK→PA14、GND→GND、3.3V→STM32 3V3）。先确认 5V 没有误接 STM32 的 3V3。
3. 点击 PlatformIO 的 **Build**（对勾），然后点 **Upload**（向右箭头）。终端显示 `SUCCESS` 即表示烧录完成。
4. 看 STM32 的 PA4 用户 LED：刚启动时先**快速闪三下**，说明新程序开始运行。此后，**每隔约 3 秒快速闪三下**＝灰度板有应答；**亮 3 秒、灭 3 秒**＝未检测到灰度板，先检查灰度板 5V、共地、SCL/SDA 是否接反及上拉跳线。

板上的电源指示灯持续亮并不代表传感器通信成功；只看 PA4 用户灯的闪烁模式。测试通过后，下一步才是读取八路原始数据。

## 编码器原始计数查看

PlatformIO 环境 `encoder_probe` 每 100 ms 从 PA2（TX）输出 E1/E2 原始累计计数、采样增量、无效跳变和 A/B 电平。串口设为 115200 8N1；USB-TTL 使用 3.3 V 逻辑并与 STM32 共地。探针会将 TB6612 STBY、PWM 和方向脚拉低，不会启动电机。

E1/E2 对应左轮还是右轮尚未实测；架空车轮并在确认编码器供电和输出电平适合 STM32 后，分别手转左右轮观察哪一路变化。未确认编码器供电/逻辑电平前不要烧录运行探针；浮空输入产生的计数不能证明编码器工作正常。本次新增串口显示只完成编译，尚未烧录和实测。
