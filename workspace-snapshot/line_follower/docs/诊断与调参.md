# 诊断与调参记录

现有 UART 以115200输出文本。T 开头的记录每100 ms采集一次，队列容量8；单次写入不超过16字节并检查availableForWrite，拥塞时统计丢弃。不要把100 ms日志间隔当作20 ms内环实际执行周期。同步I²C仍会产生调度抖动。

## CSV顺序

```text
T,ms,state,mode,phase,gray,gray_valid,line_error,e1,e2,invalid,left_target,right_target,left_speed,right_speed,left_pwm,right_pwm,fault,dropped,gray_age_ms,speed_valid
```

- 时间ms；编码器为累计x4计数；目标/实际速度mm/s（串口转成整数），PWM为带方向的命令。
- gray为8位数字读数的十进制形式，1白0黑；gray_valid只在最近150ms内读取成功时为1。全白/全黑时line_error不是可用位置误差。
- speed_valid为0时速度环不活动，速度字段不代表此刻实际车速；转弯/停车可由原始编码器计数分析。
- state: 0待松键、1就绪、2按键、3测试A、4测试间隔、5测试B、6循迹、7路线、8独立泊车、9完整任务、10故障。mode=0～7；phase为完整任务当前步骤索引。
- fault: 1握手、2读取、3全白、4全黑、5配置、6路线/反馈/任务。lastMissionError另存细分原因：0无、1配置、2超时、3传感器、4反馈、5动作、6视觉。
- dropped为队列累计丢弃；lastFaultMs为故障时间。latestTelemetry保留最新快照，视觉串口启用时仍可从SWD读取，但停止该UART文本发送。

将串口软件保存的文本交给：

```powershell
& 'C:/Users/0/.platformio/penv/Scripts/python.exe' tools/telemetry_report.py 'D:/CodexWorkspace/scratch/run01.txt' --output 'D:/CodexWorkspace/outputs/car-run01'
```

输出规范CSV及诊断摘要，跳过普通提示行、统计损坏T行。报告只辅助定位，不会自动更改参数。建议每次保存起点照片、参数版本、日志及视频；改变轮径、供电、灰度高度或负载后重新验证。

先确认编码器计数与左右归属，再标定目标速度/前馈和速度PID，最后启用外环并从比例项开始调。所有标定值填写到RobotConfig.h和MissionConfig.h，模拟测试里的值不能复制到实车。
